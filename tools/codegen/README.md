# tools/codegen

Two things live here, and both exist to keep the Go API and
`web/contract/openapi.yaml` from drifting apart.

## 1. The generated server

Not in this directory — it is `internal/api/gen/`, generated by
`go generate ./internal/api/gen/` from `internal/api/gen/cfg.yaml`. It is here in
this README because the two halves are one mechanism.

```bash
make generate         # regenerate internal/api/gen/server.gen.go
make generate-check   # fail if regenerating changes anything
```

`web/mock` already carries the rule that *a handler for a nonexistent operation
does not compile*. Generating `StrictServerInterface` is what extends that rule
to Go: an operation added to the contract and not implemented stops the build at
`var _ gen.StrictServerInterface = (*Server)(nil)`, and a handler with no
operation has no method to satisfy. `make generate-check` is what makes the rule
hold in CI rather than by habit — a `make generate` that produces a diff means
the checked-in server no longer matches its source.

## 2. `differ` — the differential harness

```bash
make diff-api                                                  # starts a private mock, runs the adapter mode
go run ./tools/codegen/differ -mock http://…/api/v0 -v          # against a mock you already have
go run ./tools/codegen/differ -mock … -mode memory              # the fake-backed comparison
go run ./tools/codegen/differ -mock … -sabotage column-swap     # break one binding and require red
```

`web/mock/src/server.ts` is the stateful, schema-validated behaviour the frontends
are built against. It is the behavioural oracle for `internal/api`, because
re-deriving that behaviour by reading screens would throw it away. `differ` drives one scenario script into both servers and
compares status, the headers that matter, and the body.

### Two modes, and why the default is the second one

`-mode memory` builds the Go server over `internal/api/memory` and seeds that
fake with the world it read out of the mock. It compares the API layer: routing,
the auth and CSRF gates, pagination, filtering, ordering, envelopes and refusals.

**It proves nothing about `internal/apistore`.** This mode never touches the
adapter, so its report is byte-identical with or without it, and it never compares
the wiring an operator actually gets.

`-mode apistore` is that comparison and is the default: **PostgreSQL in a
container, migrated with goose, seeded from the same world, served through the
adapter behind the same `internal/api` server.** The only variable between the
two modes is which implementation of `api.Ports` answers, which is what makes a
difference between them attributable.

The difference between the modes: with `sessionOut` reading the wrong octet column
in `internal/apistore/convert.go`, `-mode memory` exits **0**, and `make diff-api`
exits **1** with differences naming `inputOctets` and `outputOctets` on every
session, including the counter-wrap fixture.

**There is no `both`, and the harness refuses a mock it has already driven.** The
scenario ends in mutations and the mock is stateful, so a second pass compares
against a world the first pass moved. `make diff-api` starts and kills its own
mock; the hazard is a long-lived one driven by hand.

Against an already-driven mock, the `409` on `harness.guest` is loud, but **the rest
is quiet and reads exactly like findings**: fields such as `secretLastUsedAt`,
voucher-batch counts and `freshness.state` differ because of an earlier run's own
rotations and revocations, and every one names a real field. Against a freshly
started mock the same tree reports no undeclared differences.

So the run stops before comparing anything, names the artefacts it found and gives
the restart command. A red report that means nothing is the same disease as a
green one that means nothing. `-dirty-mock-ok`
proceeds anyway and prints the caveat above the report and again beside the
verdict.

### How it is set up, and what that buys

The Go server is **seeded from the mock**, over the mock's own API, before the
scenario runs. Every timestamp in `web/fixtures` is `Date.now() ± a fixed offset`
computed at module load, so a transcribed Go copy of the ugly world would
disagree about every date the moment either process restarted — and would need
somebody to keep a second fixture set ugly.

In the adapter mode the same world is **inverted back into the three-noun
schema** (`pgseed.go`): a `Nas` becomes a `radius_clients` row and, where the
device has a MAC, an `access_points` row; a `Session` becomes a `radacct` row
that resolves back to both by address and by `Called-Station-Id`. The seeder is
written against `internal/store` and raw SQL and **never against
`internal/apistore`** — a seeder that went through the adapter would write the
same wrong column a broken binding reads, and the comparison would agree with
itself.

Two values are invented rather than carried, because no read model has them, and
both are declared where they are used: `radius_clients.address`, since the
contract's `Nas` has no address field, and `Called-Station-Id`, since it is a
RADIUS attribute rather than a Foyer record. The count of invented addresses is
printed on every run.

`pgseed.go` is a test tool that writes `radacct` and `radpostauth`, which no
product code may do. The PostgreSQL role is the guarantee: this file seeds as the
schema **owner**, into a container it created itself, and `assertOwner` refuses to
run if the connection is the application or reaper role. The application still
holds `SELECT` and nothing else.

### What "the same" means

Five classes, kept apart deliberately (`compare.go`):

| Class | Handling |
|---|---|
| Volatile — generated ids, timestamps, freshly minted tokens | normalised away; volatile keys are declared **per step**, never globally, so `id` stays compared on every read |
| Server-specific by the contract's own rules — `Problem.title`, `Problem.detail`, the *values* in `Problem.errors` | dropped. The contract says each is the server's wording and a fallback only; comparing two servers on it would be comparing noise |
| `null` vs an omitted optional property | treated as equal, **counted, and printed**. Both encodings conform for an optional nullable property; the two *required* nullables are asserted present separately |
| List order, in the adapter mode only | arrays of identified objects are compared as sets, and the number of answers where the order actually differed is **printed**. The contract defines no order for any operation: the oracle answers in fixture order, `internal/store` orders by id or by `created_at DESC`. A contract gap, printed rather than silently accepted |
| Everything else | compared exactly. A difference is a finding |

A page is not comparable between two servers that order differently — page one of
a 625-code list is a different 200 codes on each side — so list steps marked
`Collect` follow `nextCursor` to the end and compare the whole collection. The
cursor itself is never compared: opaque by contract, and a decimal offset over a
slice against a repository keyset by construction.

### The scenario drives the ugly rows

Two servers agree trivially on a tidy path. The script finds the pathological
rows **by property rather than by id** — a hardcoded `sess-orphaned-no-stop`
would pass silently the day somebody removed it — and drives:

- the session with no `Acct-Stop` that has been online for forty days;
- the wrapping byte counter;
- twenty-minute-stale interim updates;
- the controller whose credential has expired, and discovery refused from it;
- the unreachable access point, and rotation refused on it;
- the device that refuses `require_message_authenticator`;
- vouchers in every state, including revoked mid-session;
- a required walled-garden entry, which cannot be deleted.

### Divergences are filed, never accommodated

**The contract wins.** A step may declare an expected divergence and must give a
reason; the reason is printed in the report whether or not the run is green,
**together with the differences it actually covered**, because a declaration
whose numbers nobody sees hides what it excuses. An *undeclared* difference fails the run, and so does a *declared*
one that has stopped happening — because a divergence that vanishes means either
the mock was corrected (remove the declaration) or the Go server drifted towards
the defect.

**A declaration names the keys it covers.** `Keys: {"plan", "voucherId"}` accounts
for those two properties and nothing else, so a wrong byte counter on the same row
is still undeclared and still fails. An empty `Keys` covers the whole answer and
is right only where the two servers disagree about the status itself. The
vanished-divergence check also catches a declaration that only held because of the
order the scenario ran in.

`Adapter` declarations apply to the adapter mode alone. They are separate because
they are about a different pair: the memory mode's Go server is handed the
oracle's own rows and cannot disagree about them, so a difference only the adapter
mode can produce is a fact about the schema, the adapter, or a fixture the
database will not accept.

### Proving it can fail

A mode that agrees on its first run looks from outside exactly like a mode that
compares nothing. `-sabotage <kind>` breaks one binding at the port seam and **requires
the run to go red**; a green run under sabotage is itself a failure and says which
class of defect went unnoticed. The three kinds: `column-swap` (a binding reading the neighbouring column),
`device-id` (`Session.nasId` answered as the `clients.conf` row) and
`site-scope` (the scope dropped).

The sabotage lives at the seam rather than inside `internal/apistore`, so proving
the harness can fail never requires an edit to the package under test.

**`site-scope` refuses to run against a world that cannot express the defect**, and
the refusal is a finding rather than a failure. If every session, account, device
and voucher batch lives in one site, dropping the scope changes no answer — so the
harness says *that*, rather than reporting the sabotage went unnoticed, because
those two sentences mean opposite things. The same line prints on every adapter
run while the condition holds, since a harness that could not have caught
something has to say so where the result is read.

With rows in only one site, the sabotage refuses. With sessions, accounts, devices
and a voucher batch in a second site, the precondition passes, the sabotage
applies, and the run ends `the sabotage was detected`. Which one you get is a fact
about `web/fixtures` on the day you run it, which is why the condition is computed
and not written down here as a state.

### A declaration about the world computes it

**Every declaration naming a property of the world derives it, and none is typed.**
Two reasons:

- A hardcoded declaration written against a fixture defect turns the run red the
  day somebody fixes the defect — reporting a repair as a regression, with the same
  exit code as a real drift.
- A rule restated in Go drifts from the database. `pgseed.go` does not restate
  `controller_vendor_sites`' unique index: it writes the binding, and if PostgreSQL
  refuses it as a duplicate, records the refusal **under the constraint the database
  itself named**.

Six declarations are derived: `macIsRandomised` (a session whose flag disagrees
with the address's own bit), `model`/`firmware`/`lastSeenAt` and `apName` (a device
with no MAC has no `access_points` row), `ipAddress` (a device the oracle gives no
address, which the seeder must invent one for), the `authAttempt` streams (an event
`radpostauth` cannot carry), and `sessionEnded` (a voucher whose session the world
records by neither route). Each prints its measured count in its own reason.

What remains typed is **behaviour** rather than world: the oracle performing no
credential check, `REQUIRE_SESSION = false`, CSRF issued and not checked, the
`createdBy` literal, the site-default plan on `createAccount`, `budgets` the adapter
never emits, the rotation refusal the oracle does not model, and the two derived
figures in `getOverview` / `listAlarms`. None can be derived without asking the
question the step already asks, and each retires through the vanished-divergence
check with its reason printed — which is a one-line deletion and an unambiguous
message, not a repair reported as a regression.

### Coverage is reported honestly

The report prints how many of the contract's operations the scenario compares,
and lists every one it does not **with its reason**. The denominator is read off
the generated interface, so it cannot fall behind the contract. A silent gap
reads as "covered everything", which is the failure mode the list exists against.

The adapter mode does not compare `probeController` and `probeNas`: a probe result
is what a driver observed, this harness has no controller, and replaying the
oracle's answers through Go would be inventing evidence about hardware — the
failure of a hand-written NAS mock that [`docs/rules/testing.md`](../../docs/rules/testing.md)
describes.

The seeding report is part of the same discipline: it prints what the schema could
not hold, by category and by count, rather than dropping those rows quietly.

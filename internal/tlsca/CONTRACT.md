# internal/tlsca — CONTRACT

The management console's TLS certificate, generated by the application, with no
parameter the operator supplies.

## Invariants

1. **Never overwrite a certificate that is still usable.** A usable pair is loaded
   and left alone — not replaced for a missing *derived* name, not for a key type
   this package would not choose, not for anything except the three reasons in
   *What this package does not do* (expiry, a validity longer than clients accept, a
   missing *declared* name). An operator may have
   added it to a trust store, and replacing it silently is indistinguishable from
   an attacker having done so. Enforced by `O_EXCL` on the create path, so it is
   the kernel's guarantee rather than the preceding `os.Stat`'s.
2. **A certificate that is expired, or within `RenewBeforeDays` of expiry, is
   replaced.** This is the same rule, not an exception to it: never-overwrite
   protects a certificate somebody may have accepted, and an expired certificate
   protects nobody — it is a console nobody can reach. The replacement is staged
   and renamed, so a failure leaves the old pair intact.
3. **An unloadable pair is refused, never replaced.** An unreadable file is not
   *known* to be expired; it may be a wrong mount, and destroying it destroys the
   evidence.
4. **A partial state is a refusal.** One file present and the other absent returns
   an error naming both paths, writes nothing, and deletes nothing.
5. **Nothing is asked.** Subject, SANs, key type, serial, validity and file modes
   are all derived. There is no flag, no prompt and no configuration hook.
6. **The private key is never group- or world-accessible.** `0400`, enforced on
   every call — generated or loaded — and set explicitly after creation so the
   process umask cannot decide it.
7. **Empty paths mean "generate, persist nothing".** Both empty is the development
   shape; exactly one empty is a refusal.
8. **No credential and no key material is committed.** This package generates at
   run time. There is no fixture certificate anywhere under it, by construction:
   the tests generate what they need. `docs/rules/security.md` §7.

## Exported surface

```go
func EnsureSelfSigned(certPath, keyPath string, required []string) (tls.Certificate, bool, error)
func Fingerprint(cert tls.Certificate) string
func Describe(cert tls.Certificate, certPath string, generated bool) string
const MaxValidityDays = 825
const RenewBeforeDays = 60

// Serves the same certificate, but re-checks expiry on every handshake instead of
// once at startup. Inert until a caller builds its tls.Config with GetCertificate.
type Rotating struct{ ... }
func NewRotating(certPath, keyPath string, required []string) (*Rotating, error)
func (r *Rotating) Initial() (tls.Certificate, bool)
func (r *Rotating) GetCertificate(*tls.ClientHelloInfo) (*tls.Certificate, error)
```

`Rotating` adds no new rules — it applies invariants 1–3 on a different schedule.
A failed renewal keeps serving the certificate it has rather than failing the
handshake (an expired certificate is a diagnosable browser warning; a TLS alert on
the console port is not), and retries are throttled to once a minute so a read-only
filesystem cannot be hammered once per connection.

`EnsureSelfSigned`'s `bool` reports whether it generated. It distinguishes the three
outcomes **only in combination with what the caller passed** — generated with a path
is "written", generated without one is "in memory", neither is "loaded" — which is
why `Describe` exists rather than leaving each caller to compose that sentence.

`tls.Certificate.Leaf` is always populated on success, on both the generate and the
load path, so a caller can read the expiry and the names without re-parsing.

## Parameters, and where each one comes from

| Parameter | Value | Authority |
|---|---|---|
| Validity | Exactly 825 days from an hour before now, as an exact `Duration` (never `AddDate`, which drifts an hour across DST — fatal at exactly a ceiling) | **Measured** on macOS with Apple's own evaluator (see the package doc). 826 is `CSSMERR_TP_CERT_SUSPENDED` on Apple's evaluator with the certificate as its own anchor |
| Renewal window | 60 days before expiry | Argued in the package doc. `Rotating` re-checks on every handshake, so the window is lead time for clients to see the new fingerprint rather than a bet on a restart cadence |
| Key | ECDSA P-256 | Ed25519 is not verified by any shipping browser; RSA keygen is slow in a `CGO_ENABLED=0` binary on a low-power host |
| Signature | ECDSA-SHA256 | Implied by the key |
| basicConstraints | `CA:FALSE`, critical-valid | An operator trusts one certificate for one host, not an authority that can mint any name |
| keyUsage | `digitalSignature` | An ECDSA key never performs key encipherment |
| extendedKeyUsage | `serverAuth` | Apple will not use a certificate for TLS without it |
| Serial | 128 random bits, `crypto/rand` | `docs/rules/security.md` §9 |
| SANs | `localhost`, `127.0.0.1`, `::1`, hostname (+ first label, + `<label>.local`), every non-loopback global-unicast address | Derived from `os.Hostname` and `net.InterfaceAddrs` |
| Key mode | `0400` | `deploy/verify.sh` asserts every private key on that host at 400 |
| Certificate mode | `0644` | `deploy/first-boot.sh` chmods every certificate 0644 |
| Directory mode | `0700`, **only when this package creates it** | `${SECRETS}` and `${TLS}` in `deploy/first-boot.sh` |

## The asymmetries, because each looks like an inconsistency until you know why

- **The key's mode is enforced on every call; the certificate's is set at creation
  only.** Narrowing a key that is group-readable fixes an exposure. Widening a
  certificate that somebody deliberately restricted fixes nothing. This is
  `deploy/first-boot.sh`'s `keep()` split — generated conditionally, mode enforced
  unconditionally — applied where the enforcement buys something.
- **A directory this package creates gets `0700`; one that already exists is left
  alone.** Same reason. A deployment that mounts the directory at another mode keeps
  it, and the key inside is still `0400`.

## What this package does not do, and will not

- **`EnsureSelfSigned` does not renew while running.** Its expiry check happens
  once, at the call. `Rotating` is the entry point that does, and only through a
  `tls.Config` built with `GetCertificate` — which is how `cmd/foyer` serves the
  console; nothing in this package can detect a caller that does not.
- **It replaces a stored certificate for exactly three reasons, and no others.**
  It is expired or within `RenewBeforeDays` of it; it outlives `MaxValidityDays`,
  which clients treat as unusable, like an expired one; or it does not cover a name the deployment **declared** (below). An
  unwanted key type, a certificate an operator would rather not have, a derived
  name that has changed — those are reasons to *tell* somebody, not to overwrite,
  and the remedy is removing both files.
- **It does not issue a CA.** The alternative shape was weighed and rejected in the
  package doc.
- **It does not know the Docker host's address, so it is told.**
  Inside a container `net.InterfaceAddrs` reports the container's addresses only,
  and the console is published on the host's LAN address. So there are two sources
  of names, and they behave differently on purpose:

  | | Where from | Missing one is |
  |---|---|---|
  | **Derived** | this machine: hostname, interface addresses | nothing — they change whenever a container is recreated, and rotating a fingerprint on every `docker compose up` spends trust-on-first-use until it means nothing |
  | **Declared** | the `required` argument; `deploy/consolenames.sh` computes it from the host so no operator types one | **a replacement**, on the same argument as an expired certificate: a name a browser dials and the certificate lacks makes it unusable, and never-overwrite is scoped to a certificate that still works |

  Coverage, not equality — `missingNames` asks `x509.VerifyHostname`, which is the
  matcher the client on the other end of the handshake runs. Extra names in a
  stored certificate are therefore free, and only a *missing declared* name is a
  reason to touch anything.
- **It does not read configuration.** `internal/config` owns the environment; this
  package takes two strings.

## Evidence

The header comment of `tlsca_test.go` describes how each invariant is made to fail.
Three are worth naming here because each guards against a check that would look
present and not be:

- **`TestModesSurviveAHostileUmask`.** A `go test` run inherits umask 022, which
  subtracts nothing from 0644 or 0400, so without a hostile umask the explicit
  `os.Chmod` after every file creation would do real work no test could see.
- **`assertKeyIsPrivate` is stated independently of `keyMode`.** Comparing the file
  against the package's own constant is an input the harness cannot be wrong about:
  setting `keyMode = 0644` would leave that comparison green. The independent
  assertion — no group and no other bits — is the property `deploy/verify.sh`
  asserts on the host, and it goes red.
- **`TestAFailedRenewalLeavesTheOldPairIntact` puts its two files in *different*
  directories.** With both in one read-only directory the test would stay green
  against the most plausible wrong implementation — delete the old pair, then write
  the new one — because a read-only directory blocks the delete as well as the
  write. This is `docs/rules/database.md`'s "a negative test whose subject has more
  than one way to fail is a test of whichever guard fires first", in a filesystem
  instead of a SQLSTATE.

The test fixture `foreignPair` is long-lived, with its lifetime derived from
`RenewBeforeDays` rather than typed: a fixture inside the renewal window would make
every test built on it assert a replacement under a name that says there is none.

# internal/identity — CONTRACT

## Invariants

1. **Argon2id for All Passwords**: Operator passwords and guest portal accounts MUST be hashed with Argon2id (`time=3, memory=64MB, threads=4`).
2. **NT Hash Isolation**: NT hashes for 802.1X PEAP-MSCHAPv2 are stored in a dedicated `account_nt_hashes` table, envelope-encrypted with AES-256-GCM. They are NEVER stored in cleartext.
2a. **The 802.1X verifier is bcrypt, opted in per identity, and never called argon2.** `HashPAPVerifier` produces the `Crypt-Password` value FreeRADIUS's `rlm_pap` reads for RADIUS PAP from a NAS (EAP-TTLS/PAP is planned and not generated yet). Invariant 1 is unchanged — every identity still has an argon2id verifier and it is still what the portal and the console check — but an identity opted in to 802.1X is verified **by the network** against bcrypt, because `rlm_pap` has no argon2 scheme (measured, FreeRADIUS 3.2.10). The output is Go's encoding verbatim, `$2a$`, never relabelled. A password over 72 bytes is refused with `ErrPasswordTooLongForPAP` and is NEVER pre-hashed to fit.
3. **Cryptographic Randomness**: All voucher codes, session IDs, and secret tokens MUST use `crypto/rand`. `math/rand` is forbidden.
4. **Constant-Time Comparison**: Comparison of voucher codes, hashes, and token digests MUST use `subtle.ConstantTimeCompare`.
5. **No Cleartext Password Echo**: Authentication rejection responses must never echo entered passwords or credentials in logs or URLs.
6. **At most `HashConcurrency()` argon2id computations run at once**. Each costs `HashMemoryBytes` (64 MiB) for its whole duration; the unknown-username decoy pays it too. `cmd/foyer` sizes the bound from the container's memory at startup (two slots for the deployed 320M/`GOMEMLIMIT=256MiB`). A caller waits at most `DefaultHashWait` for a slot and then gets `ErrHashBusy`, which is a refusal and never a match. A stored verifier whose `m=` exceeds `argon2Memory` is `ErrInvalidHash` — the cost parameters come from the stored string, and one inflated row would spend several slots' memory while holding one.
7. **`internal/aaa` never hashes a password with this package.** The Policy API has a 1–2 s budget per Access-Request and must never queue behind console or portal sign-ins. `TestThePolicyEngineNeverHashesAPassword` reads `internal/aaa`'s source for it. A verifier the data plane checks belongs in FreeRADIUS (`rlm_pap`, bcrypt, invariant 2a).
8. **A phone sign-in code is stored as a keyed MAC, never as the code and never under an unkeyed hash** (`otp/code.go`). HMAC-SHA256 under an HKDF-SHA256 subkey of `FOYER_KEK` (`store.Keyring.PhoneCodeKey`), over the code id, the portal session's token hash and the code, compared with `hmac.Equal`. Not argon2: a six-digit code is 10^6 values, which any unkeyed hash loses to exhaustive search whatever its cost, and a 64 MiB verifier on a pre-authentication endpoint is a memory-exhaustion lever (see invariant 6). The row records the keyring entry's id so a code made before a KEK rotation still verifies.
9. **Codes are six digits from `crypto/rand` via `rand.Int`** (no modulo bias), live five minutes by default and never more than ten, allow five attempts by default and never more than ten — **spent before the MAC is read** — are single use, and a new code for a browser retires the old one. A failed send retires its code.
10. **Codes are sent only to Vietnamese mobile ranges** (`otp.NormaliseVN`: `+84` then 3/5/7/8/9 and eight more digits). The destination allowlist is the §9 default — the install's own country. A venue may **narrow** it to a subset of `otp.MobilePrefixes` (`Settings.MobilePrefixes`, `otp.InRanges`) and can never widen it: there is no second country.
11. **The spend is bounded before it happens and the bound fails closed.** Per number (default 3/h, 5/day), the site's daily ceiling and the deployment-wide cap (`Settings.GlobalDailyLimit`, `phone_spend_cap`) are counted in PostgreSQL in the same transaction that records the code; per device (default 5/h — **the MAC on the source it was claimed from**, `otp.DeviceKey`: presence proves a MAC is on the network, not that the caller is it, so a MAC alone let a stranger spend a present guest's codes; not the portal cookie either, which is free to mint) and per address (default 60/h — the device is the per-guest key, the address a flood bound; see the `otp` package comment) in process, on `internal/ratelimit.Window`, whose map is bounded. A ceiling that cannot be counted refuses the send — and so does a venue's tuned limits that cannot be read (`apistore` answers `ErrNotOffered`, never the defaults). The console's test message (`Service.SendTest`) is charged against both ceilings the same way.
11a. **Every limit is tunable only within bounds, and read per request**, because every setting is configured in the admin console. `Settings.Limits` overrides `DefaultLimits` for one venue; the bounds are the contract's `PhoneAbuseLimitsUpdate` and migration 00033's CHECKs, and none has a value of *unlimited*. The day every ceiling counts is the **site's** calendar (`Settings.Location`, `sites.time_zone`), falling back to `Config.Location` only for a store that cannot name one.
12. **No phone number, code or provider key reaches a log line or an error string.** `sms.Config` and `otp.Settings` redact themselves in `%v`; provider errors carry the provider's result code only. Tests assert all three.
13. **`sms.Fake` cannot be selected by any saved configuration.** `sms.New` builds only the two eSMS adapters; the fake is injected by a test or by the in-memory API world.
14. **The console's first-access setup code is 80 bits from `crypto/rand`, shown once and stored only as a SHA-256 digest** (`setupcode.go`). Sixteen Crockford base32 characters in four groups; `NormaliseSetupCode` folds case, drops spaces and dashes and reads `O`/`I`/`L` as `0`/`1`/`1`, so what an operator retypes from a terminal is what was printed. An unkeyed fast digest is enough here and a keyed one would not add anything: at 80 bits the space is out of reach of exhaustive search, unlike a six-digit phone code (invariant 8). The digest is compared with `subtle.ConstantTimeCompare`.
